# 第一关：灭火教学

## 已确认的设计

用户原话：

> 第一关一般是作为教学局，让玩家明白操作、目的、升级的。所以我认为第一关就在屏幕中间放个树，树上着火，玩家长按屏幕下雨五次让火熄灭然后获得金币。

- 定位：第一关为教学关，帮助玩家理解操作、目的和升级。
- 场景：屏幕中间放置一棵着火的树。
- 操作：玩家长按屏幕下雨。
- 目标：下雨五次，让树上的火熄灭。
- 奖励：火熄灭后获得金币，具体数量待定。

这一流程已覆盖“长按下雨 → 灭火 → 获得金币”。如何花费金币及验证升级效果，需要继续补充教学步骤。

## 教学流程细化建议（尚未确认）

| 阶段 | 玩家行为 | 场景反馈 | 教学意图 |
| --- | --- | --- | --- |
| 看见目标 | 进入关卡 | 画面中间一棵树正在燃烧 | 直观看到需要灭火的目标 |
| 学会操作 | 按提示在树的上方长按 | 雨滴从触摸位置落下 | 理解触摸位置与降雨位置的关系 |
| 看见作用 | 持续按住，按生成 CD 重复下雨 | 每次有效降雨后火势逐步减小 | 理解雨能灭火，也感知生成间隔 |
| 达成目标 | 累计五次有效降雨 | 火完全熄灭 | 形成清晰、短小的首次成功体验 |
| 获得奖励 | 观看奖励反馈 | 金币到账 | 理解完成目标可以获得升级资源 |
| 首次升级 | 花费刚获得的金币升级一次“速度” | 明确展示生成 CD 缩短 | 理解金币的用途 |
| 验证升级 | 对后续灭火目标再次长按 | 仍需相同次数，但降雨更快完成 | 感知升级收益，形成继续成长的动机 |

后续灭火目标可以放在本关第二阶段，也可以放在下一关，尚未决定。首次优先教“速度”是建议；“范围”可以在出现多个目标时再教，避免对单棵树升级范围却看不出作用。

## “下雨五次”的计数口径建议（尚未确认）

- 一次指一个生成周期产生的一批雨，不能等同于一个雨滴或一次重新按下屏幕。
- 建议只在该批雨实际作用于着火的树后计为一次有效降雨，长按屏幕空白处不推进灭火进度。
- 持续长按时按“速度”属性对应的 CD 自动重复生成，不要求松手再按。
- 五次有效降雨分别推进五个灭火阶段，第五次完成后火熄灭并发放金币。
- 每一批雨最多对这棵树记一次，避免一批内多个粒子命中导致立即完成五次。

首次按下是否立即生成、火势每次衰减比例、松手后 CD 的处理方式，以及移动手指的规则仍待确定。金币是否只在灭火完成时发放，暂按用户描述记录；不额外增加部分灭火奖励。

## 画面与声音建议（尚未确认）

- 触摸提示放在树上方，避免手指正好遮住火势变化；具体视角与布局待确定。
- 火势每次变小，最终出现湿润的树冠与少量余烟；不必把计数器作为主要反馈。
- 长按期间雨声平滑进入，火焰声随灭火进度降低，奖励声保持轻柔。
- 教学阶段先验证操作反馈；完成后的雨声是否继续、怎样进入持续助眠播放，另行设计。

## 待确定

- 初始范围、生成 CD、每批雨滴数量和灭火命中判定。
- 首次金币奖励、首次升级项目与价格，以及升级后的数值。
- 升级是在第一关内完成还是由关卡间流程承接。
- 第一关的完整结束条件，及升级效果验证是否属于本关。
- 是否采用上述五批有效降雨的计数建议，以及是否需要失败、计时或重置规则。
